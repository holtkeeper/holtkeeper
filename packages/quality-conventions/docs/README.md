# @holtkeeper/quality-conventions

Figures out how a project names things and reports the names that don't match. Nothing is configured up front: the check counts how each kind of name is written in the code (module constants, local variables, components, types, file names and so on, per language) and treats the dominant style as the convention. Names that break an established convention become `QualityIssue`s. When renaming one is safe, the issue also gets a `CodeChange` the user can accept.

```ts
import { analyzeQuality } from '@holtkeeper/quality'
import { conventionsCheck } from '@holtkeeper/quality-conventions'

const data = await analyzeQuality({ dir, checks: [conventionsCheck()] })
```

## How it works

1. **Files.** In a git work tree the check lists files with `git ls-files --cached --others --exclude-standard` through the `CommandRunner`, so `.gitignore` is respected. Outside git it walks the directory and skips dot directories, `node_modules`, `dist`, `build`, `vendor`, `target`, `coverage`, `__pycache__`, `.venv` and `venv`. Files over `maxFileBytes` are skipped, and at most `maxFiles` files are read.
2. **Names.** Each file is parsed with ast-grep. Every kind of name in a language is an ast-grep rule that matches the identifier node of the declaration, plus an optional predicate. A node belongs to the first kind that matches it.
3. **Styles.** `classifyCase` sorts a name into `camelCase`, `PascalCase`, `SCREAMING_SNAKE_CASE`, `snake_case`, `kebab-case`, `flatcase`, `UPPERCASE` or `mixed`. Leading and trailing `_` and `$` are ignored (`_cache`, `$el`, `class_`), and so are names with nothing else in them (`_`). A single lowercase word (`count`) fits camelCase, snake_case and kebab-case. A single uppercase word (`MAX`) fits SCREAMING_SNAKE_CASE, and a single capital letter also fits PascalCase. Such words count as compatible with each style they fit, but they are not evidence for any of them.
4. **Convention.** The dominant style of a kind is the one the most names fit. Ties go to the style with more unambiguous names. A kind **has a convention** when it has at least `minNames` classifiable names (default 10) and the dominant style covers at least `minShare` of them (default 0.8). The check reports a `ConventionStat` for every kind that has names, and issues only for kinds that have a convention.
5. **Issues.** Each outlier becomes an issue with category `convention` and rule `naming/<kind-id>`, for example `naming/module-constant`. Its `help` gives the name rewritten in the dominant style (`toCase`). Severity is `warning` when the dominant share is at least `warningShare` (default 0.95), and `info` otherwise.
6. **Renames.** A rename is suggested only for names that are not visible outside their file. It is a `CodeChange` with `confidence: 'review'` and `source: 'conventions'`. Its edits replace every reference to the binding: all over the file for module-level names, inside the enclosing function for locals. Each edit carries its exact `oldText` and a 1-based range. No change is suggested when:
   - the name is exported or otherwise public (the issue is still reported);
   - the new name already appears in the file;
   - the old name is declared twice in the file;
   - for a local, the old name is also visible from an enclosing scope;
   - a reference cannot be rewritten mechanically: shorthand destructuring, Go keyed literals, Rust shorthand field patterns, `<Icon />` becoming `<icon />`;
   - the language can refer to the name in ways the syntax tree does not show, such as Rust `"{name}"` format strings. Kotlin `"$name"` templates are parsed and renamed.

   References that need a different rewrite are expanded: `{ foo }` becomes `{ foo: FOO }`, and Rust `S { foo }` becomes `S { foo: FOO }`. Property keys, member accesses, keyword arguments and named arguments are not references and stay as they are.

## API

- `conventionsCheck(options?)` returns the `QualityCheck` named `conventions`. Its options are `minNames`, `minShare`, `warningShare`, `languages` (default `defaultLanguages`), `fileNames` (default `true`), `maxFileBytes` and `maxFiles`.
- `classifyCase`, `compatibleStyles`, `fitsCase`, `isAmbiguousCase`, `splitWords` and `toCase` are the naming utilities.
- `inferConvention(names, thresholds)` returns the dominant style, its share and the outliers of a list of names.
- `collectNames(spec, file)` and `renameEdits(spec, file, declared, newName)` are the building blocks for other tools.
- The language specs are `typescript`, `javascript`, `go`, `python`, `rust`, `java`, `kotlin` and `php`, collected in `defaultLanguages`.

## Adding a language

Write one module in `src/languages/` that exports a `LanguageSpec`, then add it to `defaultLanguages` in `src/languages/index.ts`. The spec has these parts:

- `id`, `extensions` and `parser(path)`, which returns the ast-grep language name.
- `dynamic`, for a grammar ast-grep does not bundle: `async () => (await import('@ast-grep/lang-x')).default`. Every dynamic language is registered in a single `registerDynamicLanguage` call, because ast-grep accepts only one registration per process. Parsers come from the prebuilds shipped inside the `@ast-grep/lang-*` packages, so their postinstall scripts are not needed. A language with no prebuild for the platform is skipped.
- `kinds`: `{ id, label, rule, when?, scope? }`. `rule` matches the identifier node of the declaration. `field` on an `inside` relation names the field of the _ancestor_ that holds the node, as in `inside: { kind: 'variable_declarator', field: 'name' }`. Kinds the grammar lacks are pruned from a rule, so one set of rules can serve related grammars. Set `scope: 'none'` for names that are reachable from other files.
- `identifiers`: the node kinds that may refer to a binding.
- `functionScopes`: the node kinds that open a local scope.
- `isPublic(name, file)`, which decides whether a module-level name is visible outside its file.
- Optional hooks: `reference(node, newName)` returns `'rename'`, `'skip'`, `'abort'` or `{ text }`; `hiddenReferences(scope, name)` reports references the syntax tree does not show; `fileNameKind(path)` names the file's kind.

Add a case to `src/languages/languages.test.ts` with a small snippet that lists the expected `kind:name:scope` triples.
