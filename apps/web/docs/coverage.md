# Coverage

Part of the web app's [Quality](README.md#quality) docs.

**Coverage** (`/quality/coverage`, `features/test-coverage/`, `analyses:read`) is a `FleetTable` over every readable repository. It joins `GET /api/coverage` (the newest coverage record of each repository) with `GET /api/repos`; repositories without a record stay in the table as **Not measured** (`coverageRows`: lowest line coverage first, records with nothing to cover next, unmeasured after them, and repositories with no tests by design last). A repository whose `repo.tests` turns tests off (`RepoSummary.noTests`) is a `noTests` row: Lines shows a neutral **No tests by design** tag with the reason as tooltip, Branches, the sparkline, Change and Untested files show `—`, Freshness reads **No tests by design** (`coverageFreshness` → `no-tests`), it never counts as below target and sorts last on every column but Repository.

- **Target.** Line coverage a repository should reach, the `target` option of `analyzers.coverage` (default 60). Each card of `GET /api/coverage` carries `target` when the entry that applies to its repository sets one; otherwise the table uses the entry scoped to everything from `GET /api/settings` (`orgCoverageTarget`), else the setting's default (`belowTarget`). The sheet and the hub read the repository's resolved value (`useCoverageOptions` → `resolvedCoverageTarget`) with the same fallback. The footer names the org-wide target.
- **Toolbar.** The `ScopeSwitch` (_My teams_ folds other teams' rows into one row with their median and how many are below target; its group picker is the page's group filter), a path or group search, the **Freshness** filter (it offers **No tests by design** too) and **Below 60% only** (the org-wide target in the label). Filters and the sorted column live in the URL (`parseCoverageSearch`: `q`, `freshness`, `below`, `sort`, `dir`, plus `repo` for the sheet).
- **Strip** (`coverageKpis` over the rows in scope): rows with no tests by design are left out of every figure and counted in their own **no tests by design** cell after **not measured**; median line and branch coverage of measured rows, repositories below the target (_Below 60% target_, captioned that groups and repositories may set their own), untested files, and counts per freshness state.
- **Columns.** Repository (links to the hub's Quality › Coverage), Lines (share toned like the report, good from 80%, bad below 50%, a **Below N% target** tag with the row's own target and the covered / uncovered / no-tests `SegmentBar` from `lineSegments`), Branches, a sparkline of the last 12 records (`trendValues`), Change in points since the previous record, untested files of all files, and Freshness (`coverageFreshness` from `lib/freshness.ts`: over a month or a week old, else behind HEAD when freshness saw a newer default-branch head, else current; no record reads **Not measured**) with the record's age and short sha. Every column but the sparkline sorts (`coverageSortValue`).

A row opens `CoverageSheet` (`?repo=`, J/K step through the rows in table order). Its header carries the short record id, **Open as page**, the line share as the progress bar, **Run coverage**, and **Open repository** in the ⋯ menu; the body starts with freshness, line, branch and function shares, the change and a **Below target** tag over the coverage bar with its legend. Tabs, read from `GET /api/coverage/repo`:

1. **Breakdown**: the record (sha and age, HEAD when behind, tools, changed-file coverage, files and files without tests, target, and **Trigger** / **Last run** from the record's job, `RepoCoverageView.job`, so opening the sheet or stepping with J/K never renders the full report), then the table per workspace package or top-level folder, lowest first.
2. **Files**: the files with the most uncovered lines, tagged **No tests** when no test loaded them, or with the stored `reason` instead (**Did not build**, **Dependencies did not load**, **Tests timed out**) when the tests of their Go package could not run; for callers who may write settings each row has **Exclude**, which opens `ExcludeDialog` on the file.
3. **Changes**: files whose line coverage moved by 5 points or more since the previous record.
4. **Exclusions**: the resolved `exclude` globs of `analyzers.coverage` (`coverageExcludes`) and the scope that set them, with **Add pattern** (`ExcludeDialog` without a file) and a remove button per glob (`unexcludeEntry` in `lib/exclude.ts`: the repository's own entry changes in place, a broader one is copied into a repository entry). Both apply from the next run.

**No tests by design.** When `RepoCoverageView.tests.expected` is false the sheet and the hub section show a notice with the reason and the scope that set it instead of **Run coverage** and "Not measured yet"; a stored record stays below it without the **Below target** tag. For callers who may write a `forge:path` entry (`tests.configurable`), `testsToggle` in `lib/coverage.ts` picks the action and `features/test-coverage/TestsToggle.tsx` performs it, always on the repository's own entry (`tests.entryId`) when one exists instead of adding another: while tests are expected the ⋯ menu, the empty state and the hub section offer **Mark as no tests by design…**, a dialog asking for the reason that writes `{ expected: false, reason }`; while they are off the notice offers **Expect tests again**, which removes the own entry when what applies without it (`tests.inherited`) expects tests, and otherwise writes `{ expected: true }` into it (adding it when missing), naming the broader scope it overrides when the caller may read it. Settings changes refresh the coverage and repository queries. The setting's home is this page (`pageSettingKeys.coverage`), so **Configure** shows it next to `analyzers.coverage`.

`CoverageRepoSection` is the same body for one repository in the hub's Quality tab: the headline, the trend sparkline, **Full record**, **Run coverage** and the four tabs; **Run coverage** alone until a record exists. Nothing on these pages calls an LLM.
