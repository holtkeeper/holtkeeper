# Releases overview

Part of the web app's [Releases](README.md#releases) docs.

`/releases` (`ReleasesPage`) reads `GET /api/releases/overview`: one row per repository with releases on (`releases.enabled`), joined with `GET /api/repos` for groups so the scope switch applies (_My teams_ by default, other teams fold under the table). The header has the `/` search (path, latest or next version: `filterOverview`), a ghost **Configure** (the `releases` setting), **Read the forges again** in the ⋯ menu (a background read; the page refetches every 3 s until it finishes) and, when the viewer may set up a repository that is not listed, the primary **Set up releases** (to `/releases/setup?repo=`).

The page has three parts, each over the rows in scope:

- **Strip** (`overviewCounts`): repositories that release here, how many need action, and only when present how many wait for acceptance, have a release MR open, deploy, failed a deploy or could not be read; unreleased commits on the targets (`+` when a count was capped); whether steps change the forges (_Live_) or nothing (_Dry run_, also a notice above); and when the forges were last read.
- **Queue** (`queueRows`): rows whose `needsAction` is set, as `QueueCard`s, filtered by **Needs action** or one state (waiting for acceptance, ready to tag, release MR open, deploy failed; a filter shows only with a count, `queueCounts`). A card shows the repository and its state, current → next version in mono with the bump and the reasons it is that bump, unreleased commits on the target, tasks and left-out changes, the gate line (the failing blockers, else the target pipeline), every environment with its status and the version that runs there, and **Accept {version}** only when the version waits for acceptance and `can.accept` is true (`releases:run` on the repository), **Edit notes** (with `can.run`, which is false on a read-only repository) and **Review changes** (both to the timeline). A card of a repository the forge could not read shows the error.
- **All repositories**: a `FleetTable` of every row, needing action first, then by state, then by path (`actionFirst`). Columns: repository, stage in words (`overviewTag`), latest version with its age, next version with its bump, unreleased commits on the target with the task count, the target branch pipeline in a word (`targetPipeline`), one column per environment with its status and version, and the next step (`nextStep`: a button when something waits, a quiet link otherwise; a forge error leads to Settings › Integrations). Environment columns are the union of environment names across the rows in the order they first appear (`environmentColumns`); with more than three they collapse into one `TickStrip` column with a tick per environment (`environmentTicks`). Repository, stage, latest, next, unreleased and CI sort (`overviewSortValue`), **Needs action first** restores the default order, **Stage** filters by state and **Environment** keeps rows that deploy to the chosen environments (`withEnvironments`). Environment statuses read the same everywhere (`environmentStatus`, `environmentTag`; Ready warns). A row opens the repository's timeline. Repositories the viewer may set up but that are not listed show under the table with a picker and **Set up** to `/releases/setup?repo=`.

States (`overviewState`), most urgent first: could not read the forge, deploy failed, waiting for acceptance (the flow needs an acceptance and nobody accepted the target head), ready to tag, release MR open, ready to propose, ready to deploy, deploying, released, nothing to release, released elsewhere. Helpers live in `lib/release-overview.ts`.
