# Analysis record

Part of the web app's [Quality](README.md#quality) docs.

`/analyses/$id` (`features/analyses/AnalysisPage.tsx`) shows one analysis record. The crumbs follow the kind: the shell's workspace crumb (Quality for `coverage`, `bundle`, `ci-jobs`, `branches`, `assets` and `review`; Supply chain for `depgraph`, `licenses` and `api-surface`), the kind's page (`analysisPages` in `lib/analyses.ts`), the repository (opening the hub tab and area of the kind, `recordRepoTab`) and **Record**; `stack` records lead to Supply › Stack, and kinds without a page to the hub's Overview. Records carry no sequence numbers: they are named by date, ref and commit. Under the title a line names the repository, ref, short commit, the record compared against and when and how the record was made, ending with the job's short id (8 characters, linking to Ops › Runs) and how long it took once it finished.

**Version history** (`VersionChart`) charts the repository's records of the same kind (`GET /api/analyses`, up to 200) as bars of one metric (`trendMetrics` with the page's preferred metrics, switchable when there are several; `?metric=`), oldest first, at most 24 around the record (`versionPoints`), with release tags above the bars. **A** is the compare base (`?compare=<id>`, else the previous record) and **B** the record shown: with **Pick A** a bar sets `compare`, with **Pick B** it opens that record keeping A, and **Swap** opens A compared with B. Bars that already hold A or B can't be picked.

Underline tabs (`?view=`) split the report (`splitChanges`): **Report** (everything but `changes` blocks), **Suggested changes** with their count (only `changes` blocks, shown when there are any) and **Job log** (`RecordJobLog`: the job from `AnalysisDetail.job` with status, trigger and timings, a link to it in Ops › Runs, and the read-only `JobLogView` of its latest attempt; uploads and pruned jobs say there is no log). **Run again** opens the run-job dialog for the record's analyzer and repository (`useRunJob`, `analyses:run`); for a `review` record it is **Review again** (the Reviews dialog, see [Reviews](reviews.md)). The ⋯ menu copies the link.

`features/reports/ReportView.tsx` renders any report without knowing its kind: header (subject repo, ref, compared ref; left out with `header={false}`, as on the record page), metric cards with animated values and deltas colored by `better`, and sections as anchored cards with a scroll-spy table of contents. Blocks render through `features/reports/registry.tsx`, one file per block type in `features/reports/blocks/`:

| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `chart`    | Recharts bar, stacked bar, line, area, donut; tone or categorical colors                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `treemap`  | Recharts Treemap with click drill-down, breadcrumb and an accessible list                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `timeline` | collapsible `×N` groups for folded children, Motion layout animations                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `graph`    | React Flow, dagre layered layout (`force` uses a grouped grid layout that never overlaps nodes), highlighted paths animated, minimap; capped at 250 nodes with a notice                                                                                                                                                                                                                                                                                                                                                                     |
| `issues`   | callouts by tone                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `markdown` | safe subset, no raw HTML                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `changes`  | review-style diffs per proposed change: confidence and source chips, collapsible files with old/new line numbers, unified or split layout; long minified lines of SVG, XML and HTML files shown indented under their single line number (`lib/markup.ts`), with a Formatted/Raw toggle; when `applicable` and the principal has `analyses:run`, selection (incl. \"select all safe\") and a sticky bar to download or copy a patch or open a merge request via `POST /api/analyses/:id/changes`, with conflicts shown on the affected cards |

Blocks that act on their report read `ReportContext` (`features/reports/context.ts`), which the analysis page provides with the record id, whether the principal may apply changes and, for reports with `exclude` and a principal with `settings:write`, the repository and exclude targets; without it they render read-only. Table cells of `path` columns wrap after their slashes with the folder muted (`PathText`), so long paths no longer push the other columns out; with `exclude` each such cell gets an exclude button on hover that opens `ExcludeDialog`: choose the option (e.g. skip optimization or ignore entirely) and a glob from `excludeChoices` (the file with glob characters escaped, its extension in the folder, each parent folder, the name anywhere) or type one, and it is appended to the setting for that repository (`excludeEntry`: the entry naming the repository is extended, otherwise a new one starts from the winning broader value).

**Adding a block type:** add it to the model, write `blocks/<Type>Block.tsx`, register it in `registry.tsx` and add the type to `blockTypes` in `lib/analyses.ts`. The compiler refuses a registry or list that misses a type, and `registry.test.ts` checks they match. Unknown types from a newer server show a neutral placeholder.
