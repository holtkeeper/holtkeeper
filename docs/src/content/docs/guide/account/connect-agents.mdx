## Create a token

Use one token per machine or agent, so you can revoke one without breaking the others.

1. Click <Ui>New token</Ui> in the header.
2. Name it after the machine or agent, for example `laptop`.
3. Pick when it expires: 30 days, 90 days, 1 year or never.
4. Create it and copy the secret now; it is not shown again. The dialog also shows the ready Claude Code command.

A token acts as you with read access to repositories, analyses, audits, knowledge and releases, and can propose knowledge entries and Guide rules that people review. It cannot start tasks or run release steps: those start in Chat, **Ops › Tasks**, **Roll out** in Supply chain › Libraries and the Releases screen. It never gets more than your own grants. The **Allows** column shows **Read** for every token, including older ones issued with the former release or task scopes, which now work as read tokens. With Holtkeeper's own accounts it follows your current grants, and disabling your account or signing out everywhere revokes it.

:::caution
A token authenticates only the MCP endpoint and the read-only catalog API. It cannot issue or revoke tokens. Revoke a token you no longer use from its row.
:::

### Token status

| Status       | Meaning                            |
| ------------ | ---------------------------------- |
| Active       | Valid and used.                    |
| Expires soon | Expires within 14 days.            |
| Expired      | Past its expiry; create a new one. |
| Never used   | No call has used it yet.           |

The name filter above the table narrows long lists. **Calls, 7 days** counts each token's calls.

## Report exposed secrets

Each token has a <Ui>Report exposed secrets</Ui> choice. It decides whether your agent gets `report_secret_exposure`, the tool through which it reports keys, tokens and passwords that showed up in a session, masked, so administrators rotate them.

<Screen title="Account › Connect agents › Report exposed secrets">
  <Stack>
    <Segmented items={['Under my name', 'Anonymously', 'Off']} />
  </Stack>
</Screen>

| Choice                  | Means                                                                                                                    |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Under my name (default) | Reports show your name and time and are audited as `secret_report.create`.                                               |
| Anonymously             | Reports store nothing about you and a time moved back by up to 10 minutes, and the call is left out of usage statistics. |
| Off                     | The tool is not offered to this token.                                                                                   |

Only you see the choice; administrators can neither read nor set it, and changing it is not audited. Anonymity cannot hide the token's **Last used** time (hourly), access logs of proxies in front of Holtkeeper, or that only one person may have known a secret in a small team. Next to the choice is a link to the license's Use Condition: reporting is voluntary, reports are never grounds for sanctions, and nobody may try to unmask anonymous reporters. See [Secret reports](/guide/supply-chain/secret-reports/).

With `server.secretReports: false` in the instance's config, no token gets the tool, whatever its choice.

## Add the server to your client

**Client setup** shows the endpoint and a tab per client, each with <Ui>Copy</Ui>.

<Screen title="Account › Connect agents › Client setup">
  <Stack>
    <Segmented items={['Claude Code', 'Cursor', '.mcp.json', 'curl check']} />
  </Stack>
</Screen>

For Claude Code, run:

```sh title="Claude Code"
claude mcp add --transport http holtkeeper https://holtkeeper.example.com/mcp \
  --header "Authorization: Bearer hk_mcp_…"
```

The **.mcp.json** tab gives the same server as a project file:

```json title=".mcp.json"
{
  "mcpServers": {
    "holtkeeper": {
      "type": "http",
      "url": "https://holtkeeper.example.com/mcp",
      "headers": {
        "Authorization": "Bearer hk_mcp_…"
      }
    }
  }
}
```

The **curl check** tab is a `curl` command that asks the endpoint for its tool list, so you can confirm the token works before configuring a client. **Cursor** has the JSON for its MCP settings. The endpoint speaks Streamable HTTP, so any client that supports it works. More setups are in [Agents › Connect](/agents/connect/).

## Browse the tool reference

**Tool reference** is read live from the endpoint, so it lists exactly the tools you get. Tools are split into **Your packages** (exports, versions, usages and upgrade impact of what your repositories publish), **Third-party libraries** (whether to add or upgrade a dependency, and the docs, changes, issues and source of libraries at the version each repository uses) and **Team knowledge**. Each tool shows its description and arguments, and the list can be filtered.

:::note
Agents can propose knowledge and rule changes, but people review them in Knowledge. No MCP tool starts or approves tasks, runs release steps or makes other [Inbox](/guide/home/inbox/) decisions. Agents can read Holtkeeper's review of a merge request, a task's included, with `review_status`.
:::
