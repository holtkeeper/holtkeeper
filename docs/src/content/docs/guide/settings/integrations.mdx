## Add a forge

A forge is a GitLab instance Holtkeeper reads repositories from and opens merge requests on.

1. Add the GitLab token first: <Ui>Add credential</Ui> under **Credentials**, kind GitLab. Give the bot account the rights it needs on the groups you want analyzed.
2. Click <Ui>Add forge</Ui> (needs `settings:write` over everything).
3. Enter an id (it prefixes repository names, `work:acme/checkout-web`), the GitLab URL, the token credential and, optionally, the bot username Holtkeeper posts as.
4. Save. Repositories appear once groups that include them are set up in [Groups](/guide/repos/groups/).

Each forge shows its token, how its repositories are named, the repository count and the last webhook delivery. <Ui>Edit</Ui> and delete change or remove it.

### SSH key

A forge can have an SSH key Holtkeeper issues itself: for clone and push, for signing commits, or both, with a lifetime and an optional commit identity. Issue, rotate or remove it on the forge.

## Keep webhooks delivering

Changes arrive by webhook, or by polling where no webhook delivers. GitLab disables a hook that keeps failing, for example while Holtkeeper was down. Holtkeeper checks its own hooks every 15 minutes and re-enables disabled ones by itself; the forge's hook line shows the last check: hooks checked, disabled by GitLab, re-enabled today, gone or not readable.

While some are disabled, <Ui>Re-enable now</Ui> (needs `settings:write` over everything) runs the check at once.

:::note
Re-enabling sends GitLab a test delivery of an event Holtkeeper ignores, so it never starts analyzers, triggers or release work. While a hook is disabled, its repositories fall back to polling.
:::

1. Click <Ui>Add credential</Ui>.
2. Pick the kind, name it, enter the URL and the secret.
3. Choose who may use it: everything, some groups or some repositories. When several credentials of a kind cover a repository, the most specific one wins.
4. Optionally set an expiry and rotation. GitLab tokens can rotate themselves a set number of days before they expire.

Search matches name, host or kind. **Used by** names what refers to the credential and links to it; empty means nothing does. Rows sort by status, then expiry. <Ui>Rotate</Ui>, <Ui>Edit</Ui> and <Ui>Delete</Ui> need `credentials:write`; deleting names what stops working.

| Status       | Means                                                 |
| ------------ | ----------------------------------------------------- |
| Expired      | The expiry date has passed.                           |
| Failing      | The last rotation failed.                             |
| Expires soon | It expires within 14 days.                            |
| Unused       | Nothing refers to it and nothing used it for 30 days. |
| Healthy      | None of the above.                                    |

:::caution
Secrets are sealed when saved and never shown again. The sub-navigation counts credentials that need attention: a failed rotation or test, or a secret expiring within 14 days.
:::

### What each kind is for

| Kind         | Holtkeeper uses it to                                                                                                                                                                                                         |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GitLab       | Read repositories and act on merge requests through a forge.                                                                                                                                                                  |
| Jira         | Show a ticket's title, status and type next to keys like `ABC-123` in releases. Cloud takes an email and API token, Data Center a personal access token. Nothing is ever written to Jira, and the token never reaches agents. |
| Confluence   | Read pages, and replace one marked section of a page, for trackers.                                                                                                                                                           |
| GitHub       | Index third-party libraries' docs, releases and issues. Without the library index setting naming some, every GitHub credential is used; each row shows its usage.                                                             |
| Proxy secret | Let jobs download from private registries: the egress proxy adds it to matching requests, so the secret never reaches the job.                                                                                                |

## Trackers

**Trackers** lists the trackers that are configured: name, id, entity, sources, rules, outputs and scope. A tracker reads sources such as Confluence pages, applies rules and writes outputs. Its editor, among the section's settings below, draws sources, rules and outputs as a map: drag from a source to a rule to connect them, and it calls out rules that read nothing and sources no rule reads.

## Request limits

**Request limits** (needs `settings:read` over everything) shows how hard each credential is used, refreshed every 15 seconds.

| Status                   | Means                                                                                                                                        |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Daily cap reached        | Today's tokens or cost reached the daily cap.                                                                                                |
| Cooling down until 14:20 | The provider answered "too many requests" and Holtkeeper waits.                                                                              |
| Near limit               | 90% of an hourly or daily limit used, or a rate-limit answer in the last hour (which also catches use of the same token outside Holtkeeper). |
| Within limit             | Under every limit.                                                                                                                           |
| No limit                 | No limit is set.                                                                                                                             |

Limits per minute show per hour (`300 per minute` reads `18,000 requests / hour`); AI keys count tokens. Set or change them in the request limits setting below the tables.

:::note
Without shared limits across processes, each server process counts only its own calls; the description under the table says so. Calls made with the same token outside Holtkeeper and proxy downloads are not counted.
:::

## Release webhooks and Slack

Among the section's settings you also edit where release events are sent and the tracker analyzer's options. The Slack app's tokens, review status emoji and channels have their own page: [Slack](/guide/settings/slack/).

## Who sees this section

The section needs `settings:read` or `credentials:read`. Forges, request limits and Slack need `settings:read` over everything; the credentials table needs `credentials:read` and shows only credentials whose scope you may read.
