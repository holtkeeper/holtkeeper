## Check health

The strip has one cell per check, with a status (`ok`, `needs a look`, `failing`) and a detail, then the running version and when it was checked. <Ui>Check health now</Ui> checks again.

| Check             | Listed when                     | Needs a look or fails when                                                                                                                         |
| ----------------- | ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Store             | always                          | a simple query fails.                                                                                                                              |
| Migrations        | on Postgres                     | migrations are not applied.                                                                                                                        |
| Artifacts         | an artifact store is configured | it cannot be reached.                                                                                                                              |
| Workers           | always with a key-value store   | no worker reported its disks in 15 minutes.                                                                                                        |
| Library index     | the library index is on         | it waits for GitHub quota, or its last run failed.                                                                                                 |
| Retired read-only | old read-only entries exist     | always: those entries no longer stop writes; set them again as a freeze in [People & access](/guide/settings/people/#make-repositories-read-only). |

- **Git mirrors** and the **tool cache** are broken down by worker as the workers report them; clearing them asks every worker.
- The side column shows the artifact store: an S3 bucket (endpoint host, bucket, region, prefix) or a directory, whether it is reachable, what it uses, its objects and how long Holtkeeper keeps artifacts. With a declared quota, a bar shows the share used: amber from 80%, red from 95%.
- The 7-days column shows `—` until a snapshot a week old exists; a daily snapshot is kept for 90 days.

<Ui>Clear</Ui> needs `settings:write` over everything.

## Egress proxy cache

Jobs download packages and tools through the egress proxy, which caches them. The block shows the cache's size, what it saved, the hit rate and its entries, and removes entries with `settings:write` over everything.

## Library index

Holtkeeper indexes the docs, releases and issues of third-party libraries the fleet uses, through GitHub. The block shows its state and the GitHub credentials it uses; add them in [Integrations](/guide/settings/integrations/).

## Background work

The last line says whether agents may change code and links to [Tasks](/guide/ops/tasks/#let-agents-change-code).

## Find any setting

**All keys** says how many settings exist and lists, as tags, those no page or section edits. <Ui>Show all keys</Ui> opens every non-secret setting with the value that wins and where it comes from, filterable by text and to those not at their default; each names where it is edited. Pick a group in **Resolve for** to see what applies to that group instead.

:::tip
The **Search settings** field above the Settings sub-navigation (<Kbd>/</Kbd>) finds any setting by name or key and jumps to where it is edited, even when that is another page.
:::

## Who sees this section

System needs `settings:read` over everything. Clearing storage and caches, resetting slow query statistics and changing background work need `settings:write` over everything.
