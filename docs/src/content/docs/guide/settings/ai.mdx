## Connect a provider

An AI provider is a credential: a key for an API, plus where it lives. Agents run on one of them, the one the **AI provider** setting names.

1. Click <Ui>Add provider</Ui>.
2. Pick the kind:
   - **anthropic** for the Anthropic API,
   - **anthropic-compatible** for a gateway that speaks the Anthropic Messages API,
   - **ai-sdk** for any other API, OpenAI-compatible ones included.
3. Enter a name, the endpoint URL and the key, and who may use it (everything, some groups or some repositories). Optionally an expiry date.
4. Save, then click <Ui>Test</Ui> on the card to check the key works and the provider can call tools.
5. Set the **AI provider** setting (below the budgets) to the new credential. It has one value for the whole instance.

Each provider card shows kind, endpoint, an _Agents use it_ tag on the active one, expiry, scope, rotation, this week's spend and runs, the last use and a status:

| Status       | Means                                                    |
| ------------ | -------------------------------------------------------- |
| Expired      | The expiry date has passed.                              |
| Failing      | The last test of tool use, or the last rotation, failed. |
| Expires soon | It expires within 14 days.                               |
| Unused       | Nothing refers to it and nothing used it for 30 days.    |
| Healthy      | None of the above.                                       |

:::caution
The key is sealed when you save it and never sent back to the browser. To change it, use <Ui>Edit</Ui> and paste a new one; deleting a provider names what stops working first.
:::

## Models and tiers

There is no model setting. Holtkeeper asks for a **tier** and runs the newest model of that tier the provider lists:

| Tier   | Model                | Effort | Used for                                                |
| ------ | -------------------- | ------ | ------------------------------------------------------- |
| `fast` | newest Claude Haiku  | low    | summaries, release notes, classification, one-shots     |
| `main` | newest Claude Sonnet | medium | reviews, thread replies, chat, agent tasks; the default |
| `deep` | newest Claude Opus   | high   | reviews whose depth setting asks for deep               |

<Ui>Models</Ui> on a card lists what the provider offers. When it lists no model of a tier's family,
that tier runs on the nearest tier that has one; when the listing fails, tiers fall back to fixed
model ids. Without any Claude model listed, agents do not run.

:::note
Runs on models without a price show their cost as _unknown_ on [AI spend](/guide/ops/ai-spend/), so totals understate spend for them.
:::

## Budgets

The **Budgets** block (needs `ai:read`) shows the broadest budget you may read: spend, percent and status, and a meter split by feature, darkest first, with a warning line at **Warn at** and the stop line at the weekly limit. A legend names each feature, and a pace line gives the forecast.

### Cap a group or a repository

A budget entry scoped to groups or repositories is a **cap**: a weekly limit for those repositories on top of the instance's. It never lifts them out of the broader budget.

<Screen title="Settings › AI · Caps">
  <Scroll>

| ----------------- | ---------- | --- | ------ | -------------------- | ----------------------------- |
| Payments          | Group      | $60 | $31.10 | <Meter value={52} /> | <Tag tone="ok">On track</Tag> |
| `acme/widget-kit` | Repository | $10 | $9.80  | <Meter value={98} /> | <Tag tone="warn">Close</Tag>  |

| Agent tasks       | Feature    | —   | $14.80 | 23% of the budget    | —                             |

1. Click <Ui>Add cap</Ui>. It jumps to the budget setting's entries.
2. Add an entry, pick the groups or repositories and set its weekly limit, reserve, warning share and mode.
3. Save. The cap shows in the table with its spend.

Features have no caps of their own; their rows show spend and share only. A **Preset** picker offers ready-made budgets (_default_, _learn_, _small team_).

## Agent tools

**Advanced: agent tools** lists every tool agents can call, read only: its toolset, who gets it (Reviews, Chat, Agent tasks, MCP clients) and whether it writes. Tools cannot be switched off. Under **Advanced** you also find the setting for how much of an agent's Guide knowledge notes may take.

## Who sees this section

The section needs `settings:read` or `credentials:read`. Provider cards need `credentials:read`, changing them `credentials:write`; budgets need `ai:read`. Spend in detail is on [Ops › AI spend](/guide/ops/ai-spend/).
