## What the state means

An analyzer has no switch of its own. Its state is read from [Automation](/guide/ops/automation/):

| State             | Means                                                                                                           |
| ----------------- | --------------------------------------------------------------------------------------------------------------- |
| On                | Freshness refreshes it, or an enabled trigger, schedule or merge request policy queues it for every repository. |
| Some repositories | Enabled rules queue it for some groups only.                                                                    |
| Off               | It runs only when someone starts it.                                                                            |

Rules that only react to newly found repositories do not count. To turn an analyzer on or off, change the rules or the freshness setting in Automation; to keep it away from particular repositories, use **Analyzers off** in [Policies](/guide/settings/policies/#turn-analyzers-off).

:::note
Without `settings:read` over everything, Holtkeeper cannot show you the triggers, schedules and groups, so every state comes from freshness alone.
:::

## Read the table

| Column            | Meaning                                                                                                         |
| ----------------- | --------------------------------------------------------------------------------------------------------------- |
| Analyzer          | Name, kind, and an **AI** tag when it calls a model.                                                            |
| State             | On, Some repositories or Off.                                                                                   |
| Scope · runs when | _Every repository_, the groups, or _Only when started_, over the freshness cadence and the rules that queue it. |
| Last 7 days       | _No runs_, _4 runs, all fine_, _1 of 4 failed_ (red when at least half failed) or _2 stopped by budget_.        |
| Overrides         | Options entries narrower than the organization's.                                                               |

The state tabs, the search over name and kind, **Area** and **Uses AI** narrow it. The strip counts analyzers, overrides, AI analyzers, how many need a look (failed or budget-stopped runs) and the last run. Health counts only runs you may read (`analyses:read`).

## Change an analyzer's options

Click a row, or step with <Kbd>J</Kbd> / <Kbd>K</Kbd>. The sheet shows the state, where and when it runs, and the week's health with the median duration.

      <Field label="Budgets" value="checkout-web: 180000 · admin-*: 205000" mono wide />
    </Fields>
  </Sheet>
</Screen>

| Tab       | What it shows                                                                                                                |
| --------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Runs      | The newest 20 runs you may read, each linking to the run, plus a link to [Ops › Runs](/guide/ops/runs/) filtered to it.      |
| Options   | Every entry of the analyzer's options per scope, with the same editor the analyzer's own page opens from <Ui>Configure</Ui>. |
| Overrides | Only the entries narrower than the organization's. A new one must name groups or repositories.                               |

1. Open **Options**.
2. Edit the organization's entry, or add one for some groups or repositories. Settings with presets offer a **Preset** picker above the value.
3. Save. The next run uses it.

Run-only analyzers such as the Guide have no options and say so. <Ui>Show runs</Ui> in the ⋯ menu opens Ops › Runs filtered to the analyzer.

:::tip
An option key the analyzer no longer reads shows a warning under the entry, naming where a moved key lives now.
:::

## Run an analyzer by hand

<Ui>Run analyzer…</Ui> in the header, or <Ui>Run now</Ui> on a sheet, opens the run dialog (needs
`analyses:run`). The run joins the queue; follow it in [Ops › Runs](/guide/ops/runs/).
