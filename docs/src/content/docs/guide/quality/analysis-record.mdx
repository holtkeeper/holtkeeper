Open one analysis record as a full report, compare it with any earlier record of the same kind, read its job log and apply the changes it suggests.

Every analyzer run stores a record: coverage, bundles, assets, CI, branches, reviews, and on the supply chain side dependency graphs, licenses and public API. The fleet pages show their headline numbers; the record page shows everything. Open it with <Ui>Open as page</Ui> in a side sheet, <Ui>Full record</Ui> in a repository hub, or <Ui>Details</Ui> on a row.

## Read the header

The breadcrumb follows the kind: the workspace (Quality or Supply chain), the kind's page, the repository, and **Record**. The repository crumb opens its hub at the matching area. Records have no sequence numbers; they are named by date, ref and commit.

The line under the title names the repository, the ref, the short commit, the record it is compared against, when and how the record was made (schedule, push, by hand), the job's short id, which links to [Ops › Runs](/guide/ops/runs/), and how long the job took.

## Compare two records

**Version history** charts the repository's records of the same kind as bars of one metric, oldest first, with release tags above the bars. Up to 24 bars around the shown record are drawn. When the kind has several metrics, a switch picks one.

- **A** is the base the report compares against: the previous record, unless you picked another.
- **B** is the record shown.

1. Click <Ui>Pick A</Ui>, then a bar. The report now shows B compared with that record.
2. Click <Ui>Pick B</Ui>, then a bar. That record opens, still compared with A.
3. Click <Ui>Swap</Ui> to open A compared with B.

Bars that already hold A or B cannot be picked. The choice lives in the URL, so a link opens the same comparison.

## Read the report

The **Report** tab starts with metric cards, each with its change against A colored by whether up or down is better. Sections follow as cards with a table of contents that tracks your scroll. Depending on the kind, a section holds:

| Block    | What you can do with it                                                                                      |
| -------- | ------------------------------------------------------------------------------------------------------------ |
| Metrics  | Headline numbers with their change.                                                                          |
| Table    | Sort by any header, search, group rows. Long paths wrap after their slashes.                                 |
| Chart    | Bars, stacked bars, lines, areas or donuts.                                                                  |
| Treemap  | Click a tile to drill down; a breadcrumb walks back up. An accessible list sits beside it.                   |
| Timeline | Events with repeated children folded into `×N` groups you can expand.                                        |
| Graph    | A dependency graph with highlighted paths and a minimap; large graphs are capped at 250 nodes with a notice. |
| Issues   | Callouts by tone.                                                                                            |
| Text     | Formatted notes.                                                                                             |

### Exclude a file from a report

On reports that support it, such as coverage and assets, hovering a file path shows an exclude button.

1. Hover the path and click the exclude button.
2. Choose the option, for assets for example to skip optimization or ignore the file entirely.
3. Pick a glob: the file itself, its extension in that folder, a parent folder or the name anywhere. Or type one.
4. Confirm. The glob is added to the setting for this repository, extending its own entry or starting one from the broader value.

Excluding needs permission to write settings for the repository. Without it the button does not show.
:::

## Apply suggested changes

Some analyzers propose code changes, such as optimized images and SVGs from the assets analyzer. They sit in the **Suggested changes** tab with their count; the tab shows only when there are any.

Each change carries a confidence (**safe** or needs **review**) and its source. Files collapse; diffs switch between unified and split layout. Long minified lines of SVG, XML and HTML files show indented, with a **Formatted** / **Raw** toggle.

1. Tick the changes you want, or click <Ui>Select all safe</Ui>.
2. In the bar at the bottom, choose <Ui>Download patch</Ui>, <Ui>Copy patch</Ui> or <Ui>Open merge request</Ui>.
3. If a file changed on the branch since the record was made, the affected cards show the conflict.

:::caution
Selecting and applying changes needs `analyses:run`. Review suggestions are an exception: they are applied on the forge with its own suggestion button, so their changes are read-only here.
:::

## Read the job log

The **Job log** tab shows the job that made the record: its status, trigger and timings, a link to it in Ops › Runs, and the log of its latest attempt. Uploaded records and jobs whose logs were pruned say there is no log.

## Run it again

<Ui>Run again</Ui> opens the run dialog for the record's analyzer and repository; for a review
record it reads <Ui>Review again</Ui>. Both need `analyses:run`. <Ui>⋯</Ui> copies the link to the
record.
