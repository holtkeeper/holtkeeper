## Read the table

| Column     | Meaning                                                                                                                   |
| ---------- | ------------------------------------------------------------------------------------------------------------------------- |
| Repository | The path and avatar. Opens the [repository hub](/guide/repos/repository-hub/).                                            |
| Health     | The overall state: failing, warnings, healthy or not analysed.                                                            |
| Areas      | One cell each for Security, Deps, Coverage, Bundles, Jobs, CI, Licenses and Release. A cell you may not read stays empty. |
| Fresh      | How current the newest analyses are.                                                                                      |
| Updates    | How Holtkeeper learns about changes: by webhook or by polling.                                                            |

A cell with no analysis yet reads **no record**, with two exceptions: **Bundles** reads **n/a** when the repository has no app build or published package to measure (a Go service, for example), and **Deps** reads **Pending**, **Queued**, **Running** or **Failed** with _first run_ until Renovate's first check succeeds.

A cell opens the hub area that explains it; **Jobs** opens the repository's runs in [Ops › Runs](/guide/ops/runs/). The strip counts repositories per state and ends with how many get updates by webhook and by polling.

## Filter and sort

- The **scope switch** picks _My teams_, _All I can see_ or one group. In _My teams_, repositories your teams do not own fold into one **Other teams · N** row; click it to expand.
- **Health** and **Forge** narrow the rows; the legend next to them names the colors.
- The search in the header filters by path.
- Click a column header to sort. With no sort the worst repositories come first.

Filters and the sorted column live in the URL, so a link shows the same view.

| Key                       | Does                                |
| ------------------------- | ----------------------------------- |
| <Kbd>J</Kbd> <Kbd>K</Kbd> | Move through the rows.              |
| <Kbd>↵</Kbd>              | Open the selected repository's hub. |

The header also has <Ui>Configure</Ui>, which opens Settings › Analyzers, and a <Ui>⋯</Ui> menu with <Ui>Copy link</Ui> and <Ui>Show runs</Ui>.

## Add a repository

<Ui>Add repository</Ui> opens a side sheet in three steps beside the list. The same button is on
[Groups](/guide/repos/groups/).

1. **Pick a forge.** Choose the GitLab forge the repository lives on. On the next steps <Ui>Change</Ui> goes back to it.
2. **Pick the paths.** Browse the projects the forge's token can reach, or paste paths or URLs. Pasted URLs are trimmed to paths and duplicates dropped. Holtkeeper checks access for up to 50 at a time.
3. **Pick a group.** Add the paths to an existing group or to a new one. The group's include list gets the exact paths. <Ui>Back</Ui> and <Ui>Continue</Ui> sit in the sheet's footer.

:::tip
If a path answers _not found_, the token cannot see the project. The sheet names the account behind the token so you can invite it on GitLab, then check again.
:::

### Add to a subgroup

A subgroup can be the target too; it is listed indented under its parent. A subgroup only holds its parent's members, so paths the parent does not match yet go into the parent's include list as well.

:::caution
Adding repositories changes a group's membership and needs `settings:write` over everything. Without it the button is hidden.
:::
