## Read where a value comes from

Each row is one setting with the value that wins for this repository, in words where raw JSON would read poorly, the layer it comes from and what it replaces. Layers resolve in this order, the later one winning:

| Chip         | Layer                                                        |
| ------------ | ------------------------------------------------------------ |
| Default      | Holtkeeper's built-in default (drawn dashed).                |
| Org          | Set for the whole organization.                              |
| Group …      | Set for one of the repository's groups, such as `Group web`. |
| Repo pattern | Set for repositories matching a pattern.                     |
| This repo    | Set for exactly this repository (accented).                  |

The legend above the table shows how many settings each layer wins, so it reads as the key. On a subgroup the order is Default → Org → Parent group → This group.

## Find a setting

- The **categories** column on the left groups the settings by section, each with a count. The selected category is kept in the URL.
- **All**, **Overridden here** and **Not default** switch between every setting, the ones set for this repository, and the ones that differ from the default.
- The text filter narrows by label or key.

Global settings say they have one value for all repositories and cannot be overridden here.

## Override a setting for this repository

1. Find the row and click <Ui>Override</Ui>.
2. Edit the value in the row editor. It shows what the new value replaces.
3. Click <Ui>Save override</Ui>. The row now shows <Tag tone="acc">This repo</Tag> and an accent bar.

An override of this repository can be edited inline or removed later. A value that comes from a shared entry, such as a group or pattern, opens the full entry editor instead, since changing it affects other repositories. <Ui>Full editor</Ui> opens that editor for any row.

:::caution
Overriding needs `settings:write` on the repository. Every change is recorded in the [audit log](/guide/settings/audit-log/).
:::

<Ui>Edit defaults</Ui> in the header opens Settings › Analyzers. The **Elsewhere** block under the
categories links Analyzer defaults, Policies and the Audit log, those you may open.

| Webhook       | The repository's own webhook URL with copy, who issued it and when, whether it is registered on the forge or added by hand, the last delivery and the last 24 hours. <Ui>Regenerate</Ui> issues a new URL and the old one stops working; <Ui>Turn off</Ui> removes it; <Ui>Register on GitLab</Ui> adds it to the project for you. | Polling       | How often Holtkeeper polls, with a warning when the forge's request budget slows it down, what it looks for, and the last and next poll. <Ui>Poll now</Ui> polls at once.                                                                                                                                                                                                 |
| Recent events | Webhook deliveries and polls in one table.                                                                                                                                                                                                                                                                                                                                |

A change behaves the same whether a webhook or a poll noticed it, and a change seen both ways runs once.

### When GitLab disables the webhook

GitLab stops delivering to a hook that keeps failing. A notice then says whether polling stands in or, with polling off, that no updates arrive until the hook is back:

- _Webhook disabled by GitLab — re-enabling_ while Holtkeeper retries, with the last error and the next try.
- _Webhook disabled by GitLab_ after three failed attempts, or when Holtkeeper cannot re-enable it at all. Fix it in GitLab's **Settings › Webhooks**.

<Ui>Re-enable now</Ui> tries at once. Re-enabling sends GitLab a test delivery that starts no jobs.
The header's Updates tag reads _Webhook disabled · polling_, or _Webhook disabled_ in red when
polling is off.

:::note
Reading this tab needs `settings:read` on the repository; the webhook URL, <Ui>Poll now</Ui>, <Ui>Re-enable now</Ui> and the other buttons need `settings:write`.
:::
