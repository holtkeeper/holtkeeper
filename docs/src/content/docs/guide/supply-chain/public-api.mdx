## What the page shows

Holtkeeper reads the public API of every package in your repositories: each entry point, every exported name with its declaration and doc comment. It reads the source as text; nothing is installed or built. A record is kept per release tag, and the default branch is read weekly, so you can look up any released version and what is coming next.

**Packages** is the catalog: every package with its newest version, repository, number of exports, documented share and how many versions are on record. A package opens its [library page](/guide/supply-chain/libraries/#the-library-page), whose **API**, **Changes** and **Used by** tabs show the rest.

:::caution
A package marked **removed** was dropped from its repository: two default-branch reads in a row no longer found it. It stays listed so old versions resolve, but do not add new uses. Agents are warned the same way.
:::

### Go packages

Go modules are read too. Each Go package is listed under its full import path (for example `example.com/acme/widgets/shapes`) with a **Go** tag; packages under `internal/` are tagged **internal**, and commands (`package main`) are counted but never listed. A Go package gets a version only from a module tag on the analysed commit (`v1.2.0` for the root module, `shapes/v1.2.0` for a module in `shapes/`); the default branch shows as `head`. Versions of every major (`/v2`, `/v3`) are listed together, so you can compare across a major upgrade. The declaration sheet shows the Go import line, and **Used by** shows which packages of a module other repositories call. A Go service with nothing importable shows **Internal only** on its repository overview instead of an empty catalog.

## Find an export

**Symbol search** finds exports by name or by words in their doc comments.

1. Open **Symbol search** and type a name or a few words.
2. Narrow with the facets: package, entry point, kind, match (name or doc words) and newest release or default branch. Each facet shows its count.
3. Turn on <Ui>Include deprecated</Ui> to see exports marked deprecated, and pick a sort.

The search, facets and the open symbol live in the URL, so a link shows the same results.

<Ui>Find usages</Ui> shows the code in other repositories that uses the export.
<Ui>Compare versions</Ui> diffs the package between two versions: removed, changed, deprecated and
added exports, with a warning when the version number does not match the change.

## Fill the record

- <Ui>Analyse now</Ui> queues the `api-surface` analyzer now instead of waiting for the weekly run.
- <Ui>⋯</Ui> › <Ui>Analyze past releases</Ui> reads older release tags, so History and comparisons
  reach further back.
- <Ui>⋯</Ui> › <Ui>Reread records</Ui> reads the stored records again.
- <Ui>Configure</Ui> opens the `api-surface` analyzer's options: which packages to keep (`packages`,
  such as `@acme/*`), which folders to skip (`exclude`) and whether private workspace packages count
  (`includePrivate`, on by default).

:::tip
Coding agents read the same catalog over MCP with `search_symbols`, `get_package_api`, `list_versions` and `diff_versions`, so they look up your APIs instead of reading `node_modules`. See [Agents › Tools](/agents/tools/).
:::
