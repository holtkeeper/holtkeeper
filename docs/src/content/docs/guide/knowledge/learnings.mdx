See the one-sentence rules Holtkeeper learns from replies to its review comments, from merged merge requests and from agents, approve or reject them before they activate, and watch which ones earn their place.

A learning is a short imperative rule with its sources. Learnings are kept apart from the [rules](/guide/knowledge/rules/) people write: agents read them last, under a **Learned rules** heading, and follow them unless a written rule says otherwise. Approval is a delay, not a gate, and a learning nothing confirms expires.

## Where learnings come from

| Origin       | How                                                                                                                                                                                                                                                                   |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Review reply | Someone replies to a Holtkeeper review comment with a lasting rule: "we don't do X here", "this is intentional because…", "don't flag this". Thanks, "fixed" and questions never pass a cheap filter; a small AI call turns the rest into one sentence without names. |
| Rule miner   | The `rule-miner` analyzer reads the review threads of merged merge requests and keeps the comments that led to a code change. At most 10 learnings on a repository's first run, then at most 5 every 14 days.                                                         |
| Agent        | A coding agent calls `propose_learning` over MCP with the rule, a reason and optionally the files it is about. No AI call is made.                                                                                                                                    |
| Person       | <Ui>New learning</Ui> with `knowledge:write`. It is active at once.                                                                                                                                                                                                   |

A new learning that repeats an existing one (the same text, or most of the same words) creates nothing: its sources are merged into the existing learning, which counts as a confirmation.

## Lifecycle

| Status   | Meaning                                                                                                                                                                                        |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pending  | New. It waits `learnings.approvalDelayDays` (default 3), then becomes active by itself. People with `knowledge:write` approve or reject it earlier here or in the [Inbox](/guide/home/inbox/). |
| Active   | Agents read it.                                                                                                                                                                                |
| Expired  | It went `learnings.expiryDays` (default 90) without being confirmed and left the prompts. A confirmation brings it back.                                                                       |
| Rejected | Never used. A rejected learning still catches duplicates, so the same rule is not learned again.                                                                                               |

A learning is **confirmed** when a review comment citing it gets fixed, when someone reacts 👍 to such a comment, or when a new source teaches the same rule. Both settings are in [Settings › Policies](/guide/settings/policies/) on the **Learnings** card; a delay of `0` activates new learnings at once.

- **Sources** link to the merge request notes that taught it.
- **Uses** counts review comments that cited it (`[learn:<id>]`); **acted on** counts those whose finding was fixed.
- <Ui>Edit</Ui> changes the text, scope and files. <Ui>Reject</Ui> takes it out of the prompts.

Active learnings are ranked by fixed citations, uses, votes and sources, then by how recently they were confirmed. They share at most 3,000 of the prompt's 12,000 characters; the lowest ranked are dropped whole, and the [effective prompt](/guide/knowledge/rules/#check-the-effective-prompt) shows which.

:::tip
A learning that keeps proving itself is a candidate for a written rule: move it into the repository's `AGENTS.md` or a panel [rule](/guide/knowledge/rules/), then reject the learning.
:::
