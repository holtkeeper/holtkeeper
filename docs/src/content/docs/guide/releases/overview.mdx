## What the page shows

Every repository with releases turned on, in three parts. The scope switch applies to all of them: _My teams_ by default, other teams folded under the table.

- **The strip**: how many repositories release here and how many need action; when present, how many wait for acceptance, have a release merge request open, are deploying, failed a deploy or could not be read; unreleased commits on the target branches; whether steps change the forges (**Live**) or nothing (**Dry run**, also shown as a notice); and when the forges were last read.
- **The queue**: a card for each repository that waits for a person.
- **All repositories**: a table of every repository, the ones that need action first.

Search with <Kbd>/</Kbd> by path, latest or next version.

## Work the queue

Filter the queue by **Needs action** or by one state: waiting for acceptance, ready to tag, release MR open, deploy failed. A filter shows only when it has a count.

A card shows:

- the repository and its state;
- current → next version, the bump and why it is that bump (`minor ← 3 feat`);
- unreleased commits on the target, tasks and left-out changes;
- the gate line: the failing blockers, otherwise the target branch pipeline;
- every environment with its status and the version that runs there.

Its buttons:

| Button                  | Shows when                                                                     | Does                                              |
| ----------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------- |
| <Ui>Accept 8.3.0</Ui>   | the version waits for acceptance and you have `releases:run` on the repository | records your acceptance of the target branch head |
| <Ui>Edit notes</Ui>     | you may run steps and the repository is not read-only                          | opens the [timeline](/guide/releases/timeline/)   |
| <Ui>Review changes</Ui> | always                                                                         | opens the timeline                                |

A card of a repository the forge could not read shows the error instead.

Repository, stage, latest, next, unreleased and CI sort; <Ui>Needs action first</Ui> restores the default order. **Stage** filters by state and **Environment** keeps repositories that deploy to the chosen environments. A row opens the repository's [timeline](/guide/releases/timeline/).

Repositories you may set up but that do not release here yet are listed under the table with a picker and <Ui>Set up</Ui>.

## Stages

From most to least urgent:

| Stage                    | Meaning                                                                          |
| ------------------------ | -------------------------------------------------------------------------------- |
| Could not read the forge | The forge answered with an error.                                                |
| Deploy failed            | A deploy job of the latest version failed.                                       |
| Waiting for acceptance   | The flow needs an acceptance and nobody accepted the target branch head yet.     |
| Ready to tag             | The target has unreleased changes and nothing holds the version back.            |
| Release MR open          | The release merge request from the source branch is open.                        |
| Ready to propose         | The source branch is ahead of the target; a release merge request can be opened. |
| Ready to deploy          | The latest version waits for its deploy jobs.                                    |
| Deploying                | A deploy job runs.                                                               |
| Released                 | Everything released and deployed.                                                |
| Nothing to release       | No new changes.                                                                  |
| Released elsewhere       | Another tool, such as changesets or release-please, releases the repository.     |

## Turn releases on

Releases are off for every repository until someone sets them up.

1. Choose <Ui>Set up releases</Ui>, or <Ui>Set up</Ui> under the table. You need `settings:write` on the repository.
2. Follow the [flow setup](/guide/releases/flow-setup/) wizard; it reads the repository and suggests a flow.
3. Save with **Turn releases on when I finish**. The repository joins the overview.

<Ui>Configure</Ui> opens the `releases` setting for broader scopes. <Ui>⋯</Ui> ›
<Ui>Read the forges again</Ui> rereads every repository in the background; the page refreshes until
it finishes.

:::note
Holtkeeper never creates a version or starts a deploy on its own. Every step is a person's click, a CI call or an agent with the release scope.
:::

## Announce new versions in Slack

With `releases.announce` set, every new version gets a message in the channels you list, whatever created the tag: Holtkeeper, changesets, release-please or a CI job. It is set under [Settings › Integrations](/guide/settings/integrations/) and scoped like other settings.

The message has, in order: the package (or repository) and version, the previous version and a compare link, AI notes with highlights, **Breaking changes** with migration hints in italics, **Changes** grouped by changelog section, **Tasks** named by the commits, and **Will break on upgrade**: each connected repository whose code uses what the new version removed, with its current version, the number of broken uses, the exports and up to three files.

| Field                | Default               | Effect                                                                      |
| -------------------- | --------------------- | --------------------------------------------------------------------------- |
| `channels`           | none                  | Slack channel ids. Without any, nothing is announced. Invite the app there. |
| `tags`               | flow and package tags | Globs over tag names, such as `@acme/*@*`.                                  |
| `groupWindowMinutes` | 10                    | Tags found within this window make one message.                             |
| `notes`              | on                    | The AI overview, highlights, breaking changes and migration hints.          |
| `tasks`              | on                    | Tracker tasks named by the commits.                                         |
| `impact`             | on                    | The **Will break on upgrade** block.                                        |
| `language`           | review language       | Language of the AI prose; code and technical terms stay in English.         |

:::tip
The impact block needs the new version's API to be read first, so a message can wait a few minutes after the tag. When the analysis cannot finish in time the message goes out and says that compatibility analysis is still running or unavailable.
:::
