Settings are values that can differ per repository, group or the whole organization. Each key can have entries for several scopes; for a repository, the most specific covering entry wins as a whole (an exact repository, then path globs, subgroups and group intersections, groups, then everything; ties go to the newest). Keys marked **global** take one value for every repository. Values are never merged field by field, but unset fields of an object keep their defaults.

**Settings › Policies** and **Settings › Analyzers** also list keys whose home is another page, and the **Search settings** field in Settings finds every key wherever it lives. See [Settings](/guide/settings/people/) for the editors and [Policies](/start/concepts/policies/) for how scopes resolve.

:::note
This page follows the current definitions in the code, which are still moving. The settings editor in the panel always shows what your instance defines, with each key's help text.
:::

## AI and access

| Key                | Section         | Value                                                                                                                      | Default                                                             | Edited in                  |
| ------------------ | --------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | -------------------------- |
| `llm.provider`     | AI · global     | Id or name of an AI provider credential.                                                                                   | none: no agent runs                                                 | Settings › AI              |
| `llm.budget`       | AI              | `{ weeklyUsd, reserveUsd, action, warnPercent }`; `action` is `block` or `warn`. Presets `default`, `learn`, `small-team`. | $150 a week, $25 reserve, `block`, warn at 80%                      | Settings › AI              |
| `agent.tools`      | AI              | `{ knowledgeTokens }`: tokens of team knowledge in every agent task, `0` leaves it out.                                    | 1500                                                                | Settings › AI (Advanced)   |
| `tasks.write`      | AI · global     | `{ enabled, perRepoUsd, perGroupUsd, weeklyUsd, maxRepos }`.                                                               | off; $1.50 per repository, $5 per task, $40 a week, 10 repositories | Ops › Tasks                |
| `access.crossTeam` | Access · global | `off`, `metadata` or `snippets`: what everyone reads of other teams' repositories.                                         | `snippets`                                                          | Settings › People & access |

## Knowledge

| Key                    | Section   | Value                                                                                                                                                       | Default                                    | Edited in           |
| ---------------------- | --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ | ------------------- |
| `knowledge.autoAccept` | Knowledge | Knowledge kinds agent proposals are accepted for without review: `decision`, `convention`, `migration`, `quirk`, `howto`.                                   | none (`quirk`, `howto` on a fresh install) | Settings › Policies |
| `learnings.autoAccept` | Knowledge | `{ sources, scope }`: rule candidates accepted into the Guide without review when they come from `mcp` or `review-reply`; `scope` is `suggested` or `repo`. | `{ sources: [], scope: 'suggested' }`      | Settings › Policies |
| `guide.autoAccept`     | Knowledge | Guide sections whose generated text agents use without review: `general`, `testing`, `testids`, `commits`, ….                                               | none                                       | Settings › Policies |

## Analyzer options

Every analyzer with options has a key `analyzers.<kind>` (section Analyzers): a partial options object, validated field by field and stored without defaults. **Configure** on the page that owns the analyzer opens it; **Settings › Analyzers** lists them all.

| ------------------------ | --------------------- | ---------------------------------------------------------------------- | ------------------------------------------------- |
| `analyzers.bundle`       | Bundle size           |                                                                        | Quality › Bundles                                 |
| `analyzers.coverage`     | Test coverage         |                                                                        | Quality › Coverage                                |
| `analyzers.branches`     | Branches              |                                                                        | Quality › Branches                                |
| `analyzers.ci-jobs`      | CI jobs               |                                                                        | Quality › CI                                      |
| `analyzers.review`       | Code review           |                                                                        | Quality › Reviews                                 |
| `analyzers.depgraph`     | Dependencies          |                                                                        | Supply › Libraries                                |
| `analyzers.renovate`     | Renovate              | `report`, `calm`, `fresh`, `security`                                  | Supply › Libraries                                |
| `analyzers.api-surface`  | Public API            |                                                                        | Supply › Public API                               |
| `analyzers.usages`       | Package usage         |                                                                        | Supply › Public API                               |
| `analyzers.stack`        | Tech stack            |                                                                        | Supply › Stack                                    |

## Retired keys

Holtkeeper no longer reads these keys; the panel hides stored entries and refuses new values: `llm.model`, `llm.models`, `review.instructions`, `agent.instructions` (team rules now live in the Guide), `repo.readOnly` (replaced by `repo.freeze`; set freezes again), and the options of removed analyzers `analyzers.changelog`, `analyzers.delivery`, `analyzers.fleet`, `analyzers.port`, `analyzers.quality`, `analyzers.release-risk`, `analyzers.warmup`.
