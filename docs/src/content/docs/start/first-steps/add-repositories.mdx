Holtkeeper looks after the repositories in its fleet: those a team owns or consumes, plus the folders a forge includes. Every repository in the fleet is listed, analysed and kept fresh. You can add repositories one by one with **Add repository**, or give a team or a forge a folder pattern such as `acme/round/**` and let new projects join on their own.

## Add repositories by path

**Add repository** is the primary action on **Repos**. It opens a side sheet in three steps.

1. **Forge**: pick the forge the repositories live on.
2. **Paths**: either <Ui>Pick from forge</Ui>, browsing the projects the token can see, or <Ui>Paste paths</Ui>, one path or GitLab URL per line. URLs are trimmed to paths and duplicates dropped. Up to 50 paths are checked at once against the token.
3. **Where**: choose who answers for them.
   - <Ui>A team owns them</Ui>: pick the team; the exact paths go into its **Owns** list. When
     sibling repositories in the same folder already have an owner, that team is suggested.
   - <Ui>Forge fleet only</Ui>: the exact paths go into the forge's **Include** list, with no owner
     yet. Give them one later on [Repos › Teams](/guide/repos/teams/).

A path the token cannot read is not added. Invite the forge's account to the project in GitLab and add it again. A path an **Exclude** pattern of the team or the forge leaves out is listed as blocked; edit that pattern first.
:::

## Add repositories by pattern

For a team that keeps creating projects, a folder pattern saves the clicking.

- **For a team.** On [Repos › Teams](/guide/repos/teams/), edit the team and add **Owns** patterns (`acme/round/**`, `acme/*/web`) and, if needed, **Exclude** patterns (`acme/round/sandbox-*`). The dialog previews which repositories join and leave before you save.
- **For nobody yet.** Under **Settings › Integrations**, edit the forge and add **Include** patterns to its **Fleet**, with **Exclude** patterns for what to leave out. The field says how many listed repositories match now.

Holtkeeper lists each forge's fleet every 30 minutes. A project that matches for the first time joins without anyone adding it. Patterns that bring repositories in must start with a folder (`acme/**`, not `**/web`), since the forge is listed folder by folder.

## What happens next

A repository that joins the fleet gets every read-only analyzer once, on its default branch. Follow them in **Ops › Runs**. Until they finish, the repository shows as not analysed.

## Narrow by folder, not by subteam

A team's repositories usually sit in a few folders already: `acme/round/web`, `acme/round/api`. To give part of a team its own settings, rules or access, scope them to that folder (`acme/round/**`) or to a shape across folders (`acme/*/web`). The deeper folder wins over the team and over a shallower folder; see [The fleet](/start/concepts/fleet/#the-most-specific-entry-wins).

## Remove a repository

Remove its exact path from the team's **Owns** list or the forge's **Include** list, or add an **Exclude** pattern there. A repository another team still owns or consumes stays in the fleet.
