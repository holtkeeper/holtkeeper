Holtkeeper looks after the repositories its groups include. A group is a set of path patterns on one forge, usually one team, and every repository it matches is listed, analysed and kept fresh. You can add repositories one by one with **Add repository**, or give a group a pattern such as `acme/web-*` and let new projects join on their own.

## Add repositories by path

**Add repository** is the primary action on **Repos** and **Repos › Groups**. It opens a side sheet in three steps.

1. **Forge**: pick the forge the repositories live on.
2. **Paths**: either <Ui>Pick from forge</Ui>, browsing the projects the token can see, or <Ui>Paste paths</Ui>, one path or GitLab URL per line. URLs are trimmed to paths and duplicates dropped. Up to 50 paths are checked at once against the token.
3. **Group**: add the paths to an <Ui>Existing group</Ui> or a <Ui>New group</Ui> with an id such as `web`. The exact paths go into the group's include list.

## Add repositories by pattern

For a team that keeps creating projects, a pattern saves the clicking.

1. Open **Repos › Groups**, then the group.
2. Go to the **Membership** tab.
3. Add include patterns (`acme/web-*`, `acme/storefront/**`) and, if needed, exclude patterns (`acme/web-sandbox-*`).
4. Before saving, the tab previews who joins and who leaves against the last listing. Save.

Holtkeeper lists the forge for the group's members every 30 minutes; **List now** runs it at once. A project that matches for the first time joins without anyone adding it.

## What happens next

A repository a group finds for the first time gets every read-only analyzer once, on its default branch. Follow them in **Ops › Runs**. Until they finish, the repository shows as not analysed.

## Split a team into subgroups

A subgroup narrows its parent: it only ever holds the parent's members, everything scoped to the parent keeps covering it, and its own settings, grants and knowledge win over the parent's.

1. Open the root group and its **Subgroups** tab.
2. Choose **New subgroup**: a display name, a key under the parent (`web.payments`), and the parent's members as exact paths or one glob.
3. Save. To move a single repository later, use **Move to subgroup** on its row.

Subgroups go one level deep. A repository in two sibling subgroups gets a warning, because their settings would tie.

## Remove a repository

Remove its exact path from the group's include list, or add an exclude pattern on the **Membership** tab.
